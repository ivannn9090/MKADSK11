1. Analisis Kebutuhan Sistem

1.1 Latar Belakang

MKA System saat ini mengelola kegiatan On Budget dan Off Budget di lingkungan ANRI. Modul Layanan Telaah Konsep dikembangkan untuk mendigitalisasi alur layanan telaah kajian dan analisis kebijakan yang diajukan oleh unit kerja/direktorat kepada Direktorat Sistem Kearsipan, mencakup seluruh siklus mulai dari pengajuan hingga penyerahan output akhir.

2. Use Case Diagram

2.1 Aktor dan Use Case Utama

AktorUse Case
Super Admin Kelola pengguna, kelola template dokumen, kelola form dinamis global, lihat semua laporan, konfigurasi hari libur/SLA, audit log
Tata Usaha (TU) Verifikasi akun Klien, kelola form dinamis, verifikasi administrasi permohonan, input nomor/tanggal Nota Dinas, kelola antrian, tugaskan PIC, lihat dashboard TU, cetak laporan
PIC Telaah Terima/tolak penugasan, lakukan asesmen awal, tentukan skenario, susun Policy Brief, susun Nota Dinas, susun Policy Paper, update status proses, upload dokumen output, lihat SLA
Klien Registrasi akun, isi formulir pengajuan, unduh Nota Dinas, pantau timeline realtime, lihat dashboard Klien, unduh output akhir

2.2 Use Case Utama (Narasi Singkat)

UC-01: Pengajuan Permohonan Telaah

Aktor: Klien  |  Pre-kondisi: Akun terverifikasi, login sebagai Klien

Alur Normal: Klien membuka formulir dinamis → isi semua field wajib → submit → sistem generate Nota Dinas otomatis → status: Menunggu Pengiriman ke SRIKANDI

UC-02: Verifikasi Administrasi

Aktor: TU  |  Pre-kondisi: Surat resmi masuk via SRIKANDI

Alur Normal: TU buka daftar permohonan → pilih permohonan → input nomor & tanggal Nota Dinas → verifikasi → status: Terverifikasi → Masuk Antrian

UC-03: Penugasan PIC

Aktor: TU  |  Pre-kondisi: Permohonan terverifikasi, masuk antrian

Alur Normal: TU pilih antrian → tentukan jenis (Regular/Prioritas) → pilih PIC → tugaskan → sistem kirim notifikasi ke PIC → status: Ditugaskan PIC

UC-04: Proses Telaah (Skenario A & B)

Aktor: PIC  |  Pre-kondisi: PIC menerima penugasan, SLA mulai berjalan

Alur Normal: PIC terima tugas → asesmen awal → pilih skenario → susun dokumen → upload output → update status → selesai

3. Activity Diagram & BPMN Proses Bisnis

3.1 Alur Bisnis Lengkap

1
Klien registrasi akun → TU verifikasi akun
2
Klien login → isi formulir pengajuan telaah (form dinamis)
3
Sistem generate Nota Dinas Pengajuan (DOCX/PDF)
4
Klien unduh Nota Dinas → kirim via SRIKANDI (eksternal)
5
TU terima surat SRIKANDI → verifikasi administrasi → input nomor & tanggal ND
6
Permohonan masuk antrian (Regular/Prioritas)
7
TU tugaskan PIC → PIC terima penugasan → SLA mulai dihitung
8
PIC asesmen awal → pilih Skenario A atau B

🔵 Skenario A — Tidak Perlu Tindak Lanjut

SLA: 6 Hari Kerja

  1. PIC susun Policy Brief
  2. PIC susun Nota Dinas Tanggapan
  3. Upload output → Status: Selesai
  4. Status: Ditutup

Output: Policy Brief + Nota Dinas Tanggapan

🟣 Skenario B — Perlu Tindak Lanjut

SLA: 28 Hari Kerja

Tahap 1:

  1. Susun Policy Brief awal
  2. Susun Nota Dinas Permintaan Penyesuaian

Tahap 2:

  1. Kajian lanjutan mendalam
  2. Susun Policy Paper
  3. Susun Nota Dinas Hasil Telaah Akhir
  4. Upload output → Status: Selesai → Ditutup

Output: Policy Brief + Policy Paper + 2 Nota Dinas

3.2 Status Workflow Lengkap

Draft→ Menunggu Pengiriman SRIKANDI→ Menunggu Verifikasi TU→ Terverifikasi→ Masuk Antrian→ Ditugaskan PIC→ Diterima PIC→ Asesmen Awal

↓ Cabang A

Tidak Perlu Tindak Lanjut Penyusunan Policy Brief Penyusunan Nota Dinas Tanggapan Selesai → Ditutup

↓ Cabang B

Perlu Tindak Lanjut Penyusunan Policy Brief Nota Dinas Permintaan Penyesuaian Kajian Lanjutan Penyusunan Policy Paper Nota Dinas Hasil Telaah Akhir Selesai → Ditutup

5. ERD & Database Schema MySQL

5.1 Entitas Utama dan Relasi

EntitasRelasi
ltk_permohonanhas many ltk_aktivitas_log, ltk_dokumen_output, ltk_antrian; belongs to users (klien)
ltk_form_templatehas many ltk_form_field; digunakan oleh ltk_permohonan
ltk_form_fieldbelongs to ltk_form_template; has many ltk_jawaban_field
ltk_jawaban_fieldbelongs to ltk_permohonan, ltk_form_field
ltk_antrianbelongs to ltk_permohonan; has one ltk_penugasan_pic
ltk_penugasan_picbelongs to ltk_antrian, users (pic); has many ltk_asesmen
ltk_asesmenbelongs to ltk_penugasan_pic; determines skenario
ltk_dokumen_outputbelongs to ltk_permohonan, users; polymorphic type (policy_brief/policy_paper/nota_dinas)
ltk_nota_dinas_templatehas many ltk_nota_dinas_generated
ltk_sla_configglobal config SLA per skenario
ltk_hari_liburmaster hari libur nasional untuk kalkulasi HK
ltk_aktivitas_logbelongs to ltk_permohonan, users; append-only timeline
ltk_notifikasibelongs to users; polymorphic referensi

5.2 Database Schema MySQL Lengkap

Tabel: ltk_permohonan

CREATE TABLE ltk_permohonan (
  id              INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  kode            VARCHAR(30) NOT NULL UNIQUE COMMENT 'LTK-2025-0001',
  klien_user_id   INT UNSIGNED NOT NULL,
  unit_kerja_id   INT UNSIGNED NULL,
  judul           VARCHAR(500) NOT NULL,
  deskripsi       TEXT NULL,
  form_template_id INT UNSIGNED NOT NULL,
  status          ENUM(
    'draft','menunggu_srikandi','menunggu_verifikasi_tu',
    'terverifikasi','masuk_antrian','ditugaskan_pic',
    'diterima_pic','asesmen_awal',
    'tidak_perlu_tindak_lanjut','penyusunan_policy_brief',
    'penyusunan_nota_dinas_tanggapan',
    'perlu_tindak_lanjut','nota_dinas_permintaan_penyesuaian',
    'kajian_lanjutan','penyusunan_policy_paper',
    'nota_dinas_hasil_telaah_akhir',
    'selesai','ditutup'
  ) NOT NULL DEFAULT 'draft',
  skenario        ENUM('A','B') NULL,
  jenis_antrian   ENUM('regular','prioritas') NULL DEFAULT 'regular',
  nomor_nota_dinas_masuk  VARCHAR(100) NULL,
  tgl_nota_dinas_masuk    DATE NULL,
  nomor_nota_dinas_keluar VARCHAR(100) NULL,
  tgl_nota_dinas_keluar   DATE NULL,
  pic_user_id     INT UNSIGNED NULL,
  tgl_penugasan   DATETIME NULL,
  tgl_terima_pic  DATETIME NULL,
  sla_hari_kerja  TINYINT UNSIGNED NULL,
  tgl_deadline    DATE NULL,
  tgl_selesai     DATETIME NULL,
  is_sla_breach   TINYINT(1) NOT NULL DEFAULT 0,
  catatan_tu      TEXT NULL,
  created_by      INT UNSIGNED NOT NULL,
  updated_by      INT UNSIGNED NULL,
  created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME NULL ON UPDATE CURRENT_TIMESTAMP,
  deleted_at      DATETIME NULL,
  FOREIGN KEY (klien_user_id) REFERENCES users(id),
  FOREIGN KEY (form_template_id) REFERENCES ltk_form_template(id),
  FOREIGN KEY (pic_user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Tabel: ltk_form_template

CREATE TABLE ltk_form_template (
  id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  nama        VARCHAR(200) NOT NULL,
  deskripsi   TEXT NULL,
  is_aktif    TINYINT(1) NOT NULL DEFAULT 1,
  created_by  INT UNSIGNED NOT NULL,
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME NULL ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Tabel: ltk_form_field

CREATE TABLE ltk_form_field (
  id              INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  form_template_id INT UNSIGNED NOT NULL,
  label           VARCHAR(255) NOT NULL,
  field_name      VARCHAR(100) NOT NULL,
  tipe            ENUM('text','textarea','number','date','dropdown',
                       'radio','checkbox','file','pdf') NOT NULL,
  placeholder     VARCHAR(255) NULL,
  opsi_pilihan    JSON NULL COMMENT 'untuk dropdown/radio/checkbox',
  is_required     TINYINT(1) NOT NULL DEFAULT 0,
  urutan          SMALLINT UNSIGNED NOT NULL DEFAULT 0,
  is_aktif        TINYINT(1) NOT NULL DEFAULT 1,
  created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME NULL ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (form_template_id) REFERENCES ltk_form_template(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Tabel: ltk_jawaban_field

CREATE TABLE ltk_jawaban_field (
  id              INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  permohonan_id   INT UNSIGNED NOT NULL,
  form_field_id   INT UNSIGNED NOT NULL,
  nilai_text      TEXT NULL,
  nilai_file_path VARCHAR(500) NULL,
  created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (permohonan_id) REFERENCES ltk_permohonan(id),
  FOREIGN KEY (form_field_id) REFERENCES ltk_form_field(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Tabel: ltk_asesmen

CREATE TABLE ltk_asesmen (

  FOREIGN KEY (permohonan_id) REFERENCES ltk_permohonan(id),

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Tabel: ltk_dokumen_output

CREATE TABLE ltk_dokumen_output (
  id              INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,

    'nota_dinas_pengajuan',

    'policy_paper'

  tgl_dokumen     DATE NULL,

8. SLA Monitoring Design

8.1 Logika Kalkulasi Hari Kerja

Library: app/Libraries/Ltk/SlaCalculator.php

Aturan:

  • Hari kerja = Senin–Jumat, bukan hari libur nasional (ltk_hari_libur)
  • SLA mulai dihitung saat PIC menerima penugasan (tgl_terima_pic)
  • Deadline = tgl_terima_pic + N hari kerja
  • Skenario A: 6 HK  |  Skenario B: 28 HK

Method utama:

  • addWorkingDays(DateTime $start, int $days): DateTime
  • countWorkingDays(DateTime $start, DateTime $end): int
  • getRemainingWorkingDays(int $permohonanId): int

15. Rekomendasi Arsitektur & Best Practice

15.1 Arsitektur Sistem

Pattern: Service Layer + Repository-like Model (CI4 native)

  • Controller: thin, hanya route request ke Service/Model
  • Model: query builder, scope methods, tidak ada business logic
  • Library/Service: WorkflowEngine, SlaCalculator, NotaDinasGenerator — seluruh business logic terpusat di sini
  • Event System: gunakan CI4 Events untuk trigger AktivitasLogModel dan NotifikasiModel secara decoupled

15.3 Best Practice Pengembangan

AreaRekomendasi
DatabaseSoft delete pada ltk_permohonan; JSON hanya untuk opsi pilihan, bukan data kritis; Index wajib pada FK dan kolom filter
KeamananValidasi tipe MIME file upload (tidak hanya ekstensi); CSRF token pada seluruh form; sanitasi output di View; Shield JWT untuk API
File UploadSimpan di luar public/ (e.g. writable/uploads/ltk/); serve melalui controller dengan cek otorisasi; max ukuran per tipe
Generate DokumenQueue job untuk generate DOCX/PDF besar; simpan hasil ke disk dan beri URL download; jangan generate ulang jika sudah ada
SLASimpan tgl_deadline di DB (bukan dihitung runtime); update cron harian; tampilkan countdown di UI menggunakan JS
TestingUnit test untuk SlaCalculator (edge case weekend, libur); Feature test workflow transitions; Validation test form field types
MigrasiPrefix semua tabel modul dengan ltk_ untuk isolasi; satu file migrasi per tabel
