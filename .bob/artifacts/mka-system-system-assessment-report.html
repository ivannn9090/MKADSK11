1. Executive Summary

MKA System adalah aplikasi Monitoring Kegiatan Internal yang dikembangkan untuk Direktorat Sistem Kearsipan ANRI. Sistem ini telah berkembang dari monitoring kegiatan on-budget/off-budget sederhana menjadi platform terintegrasi yang mencakup manajemen anggaran, dokumen, jadwal, dan layanan telaah konsep kebijakan.

✅ Arsitektur RESTful API + SPA sudah tepat dan skalabel
✅ Modul LTK memiliki workflow engine 21 status yang lengkap
✅ JWT custom dengan RBAC 8 role berfungsi baik
✅ Integrasi Google Calendar OAuth2 sudah berjalan
⚠️ Tidak ada unit test — risiko regresi tinggi
⚠️ Token disimpan di localStorage — risiko XSS
ℹ️ SERASI SharePoint integration belum dimanfaatkan optimal
ℹ️ Pelaporan belum mencakup dashboard eksekutif visual
Penilaian Keseluruhan: Sistem berada pada kondisi Production-Ready dengan Kompleksitas Tinggi. Kematangan teknis di atas rata-rata untuk sistem internal pemerintah. Prioritas utama pengembangan berikutnya adalah stabilisasi (testing, security hardening) dan peningkatan UX mobile.

4. Arsitektur Sistem

4.1 Pola Arsitektur

Backend

  • Framework: CodeIgniter 4 (PHP 8.3)
  • Pola: RESTful API — setiap fitur punya endpoint JSON
  • Auth: Custom JWT HS256 tanpa library eksternal
  • ORM: CI4 Query Builder + Model
  • Base Controller: BaseApiController — RBAC, helpers, audit log
  • Database: MySQL, soft-delete (deleted_at)

Frontend

  • Pola: SPA — single app.php shell, routing via JS switch
  • Framework CSS: Bootstrap 5 + AdminLTE
  • Routing: loadPage(page) di core.js
  • State: localStorage (mka_token, mka_user)
  • API Layer: apiGet/apiPost/apiPut/apiDelete wrappers
  • Calendar: FullCalendar 6 (lazy CDN)

8. Security Review

8.1 Temuan Keamanan

KategoriStatusDetailRekomendasi
SQL InjectionMitigasiCI4 Query Builder menggunakan parameter bindingHindari raw query string, audit semua query($sql)
XSSRisiko Mediumesc() helper digunakan di frontend. Tapi innerHTML digunakan secara masif di JS modulesGunakan textContent untuk data user, audit innerHTML
CSRFAPI Tidak RentanAPI stateless JWT tidak memerlukan CSRF tokenPastikan SameSite cookie jika pindah ke cookie-based auth
JWT SecurityPerhatianCustom JWT implementation, bukan library standar (php-jwt). Token di localStorage rentan XSSAudit implementasi JwtLibrary, pertimbangkan HttpOnly cookie
Broken AuthMitigasiJwtAuthFilter di semua route, requireRole() di setiap endpointTambahkan rate limiting pada login endpoint
Broken AuthorizationPerhatianAdmin bypass total semua role check — potensi privilege escalationTambahkan audit log khusus untuk aksi admin sensitif
File UploadParsialTidak terlihat validasi MIME type eksplisit pada upload dokumenValidasi MIME + ekstensi + max size, rename file, simpan di luar webroot
Sensitive DataPerhatianGoogle client_secret tersimpan plain text di DB. access_token Google juga plainEnkripsi kolom sensitif di DB (AES-256)
PasswordAmanBcrypt hashing, must_change_password flag tersediaEnforced password policy (min length, kompleksitas)
OTPAman6-digit, expiry tersimpan, purpose-taggedTambahkan rate limit OTP request per email
🔴 Prioritas Tinggi: Token JWT disimpan di localStorage. Jika ada XSS di salah satu halaman, seluruh sesi bisa diambil alih. Pertimbangkan migrasi ke HttpOnly cookie untuk token penyimpanan, atau setidaknya implementasi Content Security Policy (CSP) yang ketat.

9. Technical Debt & Code Review

9.1 Kelebihan Teknis

  • Arsitektur RESTful konsisten — semua operasi via JSON API
  • BaseApiController sangat efektif mengurangi duplikasi auth + response format
  • Migration system terstruktur (54 file, naming convention konsisten)
  • Soft delete konsisten di seluruh tabel utama
  • Audit log terintegrasi di controller via auditLog()
  • LTK WorkflowEngine sebagai state machine — desain yang tepat
  • GoogleCalendarService pure cURL tanpa SDK eksternal — ringan dan terkontrol
