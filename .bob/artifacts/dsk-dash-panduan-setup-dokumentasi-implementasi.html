TAHAP 1 — Composer Install

Pastikan Google API Client Library sudah terinstall. Jalankan di root project:

composer require google/apiclient:^2.15

Verifikasi:

composer show google/apiclient

TAHAP 2 — Jalankan Migration

Migration AddGoogleSyncErrorToSchedules sudah dijalankan dan kolom google_sync_error sudah ada di tabel schedules.

Jika perlu di-reset atau dijalankan ulang:

php spark migrate

Verifikasi kolom:

php spark db:table schedules

Kolom yang harus ada di tabel schedules:

  • google_event_id — ID event dari Google Calendar
  • google_calendar_id — Calendar ID target
  • google_sync_status — pending / synced / failed
  • google_synced_at — timestamp terakhir sync berhasil
  • google_sync_error — pesan error terakhir (aman, tanpa credential)

TAHAP 3 — Google Cloud Console Setup

1
Buat / Pilih Google Cloud Project
Buka console.cloud.google.com, login dengan akun Google yang Calendar-nya akan dipakai, buat project baru atau pilih yang sudah ada.
2
Enable Google Calendar API
Masuk ke APIs & Services → Library, cari Google Calendar API, klik Enable.
3
Konfigurasi OAuth Consent Screen
Masuk ke APIs & Services → OAuth consent screen. Pilih External (atau Internal jika Google Workspace). Isi App Name, User Support Email, Developer Contact. Tambahkan akun Google Anda sebagai Test User jika status aplikasi masih Testing.
4
Buat OAuth Client ID
Masuk ke APIs & Services → Credentials → Create Credentials → OAuth Client ID. Pilih Application Type: Web application. Beri nama misal: Agenda Web.

Tambahkan Authorized Redirect URI (gunakan URL aplikasi Anda): 
http://localhost/DSK-DASH/public/google-oauth-callback
⚠️ URL harus sama persis termasuk http/https, path, dan tanpa trailing slash. Untuk production gunakan HTTPS.
5
Salin Client ID dan Client Secret
Setelah OAuth Client dibuat, salin Client ID dan Client Secret — akan diisi ke file .env di langkah berikutnya.

TAHAP 4 — Konfigurasi .env

Edit file .env di root project, tambahkan / isi konfigurasi berikut:

# ── Google Calendar Integration ──────────────────────────────────
GOOGLE_CLIENT_ID="YOUR_CLIENT_ID_DARI_GOOGLE_CLOUD"
GOOGLE_CLIENT_SECRET="YOUR_CLIENT_SECRET_DARI_GOOGLE_CLOUD"
GOOGLE_REDIRECT_URI="http://localhost/DSK-DASH/public/google-oauth-callback"
GOOGLE_CALENDAR_ID="primary"
⚠️ Jangan commit .env ke repository. Pastikan .env ada di .gitignore.

Setelah diisi, halaman Settings → Integrasi Google Calendar di web akan menampilkan:

  • ✓ Client ID — Terdeteksi
  • ✓ Client Secret — Terdeteksi
  • ✓ Redirect URI — Terdeteksi
  • ✓ Calendar ID — Terdeteksi

TAHAP 5 — Hubungkan Google Calendar (OAuth Flow)

1
Buka halaman integrasi di web
Login sebagai admin → Settings → Integrasi → Google Calendar.
2
Klik tombol "Hubungkan Google Calendar"
Browser akan redirect ke halaman login Google. Login dengan akun Google yang Calendar-nya akan dipakai.
3
Berikan izin akses
Google akan meminta izin membuat, mengedit, dan menghapus event di kalender Anda. Klik Allow / Izinkan.
4
Callback dan simpan token
Google redirect ke google-oauth-callback. Halaman tersebut otomatis:
  • Memvalidasi state OAuth (anti-CSRF)
  • Menukar authorization code dengan access + refresh token
  • Menyimpan refresh token ke database (terenkripsi)
  • Menutup tab secara otomatis setelah 3 detik
Setelah berhasil, status di halaman Settings menjadi ● Terhubung.

TAHAP 6 — Tes Koneksi

Di halaman Settings → Integrasi → Google Calendar, klik tombol [Tes Koneksi].

Sistem akan memverifikasi:

  • Access/refresh token masih valid
  • Calendar ID dapat diakses
  • Permission mencukupi (create/update/delete events)

Hasil sukses: ✓ Google Calendar berhasil terhubung

Hasil gagal akan menampilkan penyebab: token kedaluwarsa, Calendar ID salah, permission kurang, dll.

TAHAP 7 — Uji Create / Edit / Delete Agenda

Create Agenda
  1. Buka modul Agenda → klik tombol Buat Agenda
  2. Isi form dan simpan
  3. Sistem menyimpan agenda ke database CI4
  4. Sistem otomatis membuat event di Google Calendar
  5. Status kolom google_sync_status menjadi synced
  6. Di detail agenda tampil badge Synced dan waktu sync terakhir
  7. Buka Google Calendar — event harus muncul
Edit Agenda
  1. Edit agenda yang sudah memiliki google_event_id
  2. Sistem meng-update event yang sama di Google Calendar (tidak membuat event baru)
  3. Status tetap synced, google_sync_error dibersihkan
Delete Agenda
  1. Hapus agenda dari modul Agenda
  2. Jika agenda memiliki google_event_id, sistem mencoba hapus event dari Google Calendar
  3. Jika event sudah tidak ada di Google Calendar (404), sistem tetap melanjutkan hapus lokal tanpa error
  4. Agenda lokal terhapus (mengikuti soft-delete/hard-delete existing)
Retry Sync (agenda gagal)
  1. Agenda dengan google_sync_status = failed menampilkan badge Sync Failed dan tombol 🔄 di detail modal
  2. Klik tombol 🔄 → sistem mencoba sync ulang satu agenda
  3. Atau gunakan tombol [Sinkronkan Agenda] di halaman Settings untuk sync batch semua agenda pending/failed

TAHAP 8 — Disconnect Google Calendar

Di halaman Settings → Integrasi → Google Calendar, klik [Putuskan Koneksi].

  • Token OAuth dihapus dari database
  • Agenda lokal tidak terhapus
  • google_event_id yang sudah ada dipertahankan sebagai referensi historis
  • Status integrasi menjadi Tidak Terhubung
  • Untuk reconnect: klik kembali tombol Hubungkan Google Calendar

Struktur Token Storage

Token OAuth disimpan di tabel google_calendar_settings (sudah ada sebelumnya). Refresh token dienkripsi menggunakan CI4 Encryption service sebelum disimpan. Access token tidak disimpan ke database — selalu di-generate ulang dari refresh token saat dibutuhkan. Token tidak pernah dikirim ke browser atau dicatat di log.

Flow Sinkronisasi (Ringkasan)

Admin buat/edit/hapus Agenda
       ↓
ScheduleController (validasi + simpan ke DB CI4)
       ↓
DB CI4 = SOURCE OF TRUTH
       ↓
GoogleCalendarService::syncAgenda() / deleteEvent()
       ↓
Google Calendar API
       ↓
Berhasil: google_sync_status = synced, google_event_id tersimpan
Gagal:    google_sync_status = failed, google_sync_error tersimpan
          Agenda TETAP tersimpan — tidak rollback

Catatan Environment Production

  • Ganti http:// → https:// di GOOGLE_REDIRECT_URI dan di Google Cloud Console
  • Update GOOGLE_REDIRECT_URI di .env ke domain production
  • Tambahkan URL production ke Authorized Redirect URIs di Google Cloud Console
  • Uncomment // 'forcehttps' di app/Config/Filters.php bagian $required['before']
  • Set CI_ENVIRONMENT = production di .env
  • Pastikan CI4 file cache dapat di-write (writable/cache/) untuk rate limiter
