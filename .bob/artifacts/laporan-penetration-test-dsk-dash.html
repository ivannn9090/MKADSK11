Detail Temuan

HIGH PT-01 — SQL Injection ✓ Fixed
OWASP A03:2021 — Injection  |  KegiatanController.php:145   RoController.php:91
Deskripsi

Variabel $id dari route parameter diinterpolasi langsung ke dalam raw SQL query tanpa parameterized binding.

// VULNERABLE:
$countOB = $db->query("SELECT COUNT(*) AS c FROM off_budget_sumber WHERE sumber_id = $id")
$this->db->query("UPDATE kegiatan SET ro_id = NULL WHERE ro_id = $id")
Fix: Ganti dengan parameterized query menggunakan ? placeholder:
$db->query("... WHERE sumber_id = ?", [$id])
HIGH PT-02 — Path Traversal di Download Endpoint ✓ Fixed
OWASP A01:2021 — Broken Access Control  |  Ltk/DokumenController.php:246
Deskripsi

Path file diambil dari database (file_pdf_path), lalu langsung digabung ke WRITEPATH . 'uploads/' tanpa sanitasi. Jika database dikompromikan atau path dimanipulasi, file di luar direktori uploads bisa diakses — termasuk .env, log, dll.

// VULNERABLE:
$absPath = WRITEPATH . 'uploads/' . $relPath;  // tidak ada realpath() check
Fix: Tambahkan realpath() dan validasi bahwa path final berada di dalam WRITEPATH/uploads/. Tambah sanitasi filename untuk Content-Disposition header.
HIGH PT-03 — JWT Tanpa Token Revocation / Blacklist ✓ Fixed
OWASP A07:2021 — Identification and Authentication Failures  |  AuthController.php::logout   JwtAuthFilter.php
Deskripsi

JWT bersifat stateless dan valid hingga waktu exp. Ketika user logout, token lama masih dapat digunakan hingga 24 jam ke depan (sesuai jwt.expiry = 86400). Jika token dicuri, penyerang dapat terus menggunakan token meski korban sudah logout.

Fix: Buat tabel revoked_tokens yang menyimpan SHA-256 hash token yang di-logout. JwtAuthFilter mengecek blacklist setiap request. Cleanup otomatis saat token expired. AuthController::logout merevoke token aktif.
HIGH PT-04 — OTP Brute-forceable ✓ Fixed
OWASP A07:2021 — Auth Failures  |  OtpModel.php
Deskripsi

OTP 6 digit menghasilkan hanya 1 juta kombinasi. Dengan rate limit 10 req/60s, penyerang dapat melakukan exhaustive attack dalam ~1.67 jam (6,000 req/jam). Tidak ada mekanisme burn-on-fail.

Fix: OTP diupgrade ke 8 digit (100 juta kombinasi). Tambah burn-on-fail: OTP dinonaktifkan (used=1) setelah satu percobaan gagal, memaksa user meminta OTP baru.
MEDIUM PT-05 — Demo Credentials Hardcode di Halaman Login ✓ Fixed
OWASP A05:2021 — Security Misconfiguration  |  Views/auth/login.php:77-82
Deskripsi

Halaman login menampilkan akun dan password demo secara publik: admin@instansi.go.id / admin123, password123. Jika password production tidak diubah, penyerang dapat langsung login sebagai admin.

Fix: Hapus seluruh blok <div class="demo"> dari halaman login.
MEDIUM PT-06 — OTP Validation Mismatch ✓ Fixed
Logic Error  |  AuthController.php::verifyOtp:267
Deskripsi

OTP telah diupgrade ke 8 digit di OtpModel, tetapi validasi di AuthController::verifyOtp masih menggunakan exact_length[6]. Akibatnya, semua verifikasi OTP baru pasti gagal karena input 8 digit tidak lolos validasi 6 digit.

Fix: Ubah 'otp' => 'required|exact_length[6]' menjadi exact_length[8]. Juga perbaiki login validation dari min_length[6] ke min_length[8].
MEDIUM PT-07 — XSS di Email Template ✓ Fixed
OWASP A03:2021 — XSS  |  Libraries/EmailService.php
Deskripsi

Parameter $toName dan $appName yang berasal dari input user dan database disisipkan langsung ke dalam HTML email tanpa escaping. Penyerang yang memanipulasi nama akun bisa menyuntikkan HTML/JS ke email yang dikirim ke user lain.

Fix: Semua variable user-supplied di-escape menggunakan htmlspecialchars($val, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8') sebelum dimasukkan ke body HTML email.
MEDIUM PT-08 — Settings API Tanpa Whitelist Key ✓ Fixed
OWASP A04:2021 — Insecure Design  |  AdminController.php::settingsUpdate
Deskripsi

Endpoint POST /api/v1/admin/settings menerima key apapun dan menyimpannya ke tabel app_settings. Admin yang berhasil dikompromi dapat menulis key arbitrer seperti konfigurasi internal yang tidak seharusnya diubah via API.

Fix: Tambahkan whitelist $allowedKeys. Request dengan key di luar whitelist dikembalikan dengan HTTP 422.
MEDIUM PT-09 — Security Headers Tidak Aktif ✓ Fixed
OWASP A05:2021 — Security Misconfiguration  |  Config/Filters.php
Deskripsi

Filter secureheaders tersedia di CI4 tetapi di-comment-out di $globals['after']. Tanpa header ini, aplikasi rentan terhadap clickjacking (X-Frame-Options), MIME sniffing (X-Content-Type-Options), dan tidak memiliki Referrer-Policy.

Fix: Aktifkan 'secureheaders' di $globals['after']. CI4 SecureHeaders menambahkan: X-Frame-Options: SAMEORIGIN, X-Content-Type-Options: nosniff, X-XSS-Protection: 1; mode=block, Referrer-Policy: same-origin.
MEDIUM PT-10 — CSRF tokenRandomize = false ✓ Fixed
OWASP A01:2021 — CSRF  |  Config/Security.php
Deskripsi

Dengan tokenRandomize = false, token CSRF tidak berubah antar request. Jika token bocor sekali (melalui log, referer header, dsb.), penyerang dapat menggunakannya berulang kali.

Fix: Set public bool $tokenRandomize = true — token baru setiap request.
MEDIUM PT-11 — Tidak Ada Rate Limiting di Auth Endpoint ✓ Fixed
OWASP A07:2021 — Auth Failures  |  Config/Routes.php
Deskripsi

Endpoint auth/login, auth/verify-otp, auth/register, auth/send-otp, dan ltk/klien/register tidak memiliki pembatasan request, memungkinkan credential stuffing dan OTP brute-force tanpa hambatan.

Fix: Implementasi RateLimit5Filter (5 req/60s) dan RateLimit10Filter (10 req/60s) berbasis CI4 file cache per IP per endpoint. Response HTTP 429 dengan header Retry-After.
LOW PT-12 — Password Minimum 6 Karakter ✓ Fixed
OWASP A07:2021 — Auth Failures  |  AdminController.php UserController.php AuthController.php
Deskripsi

Beberapa endpoint validasi password menggunakan min_length[6]. Password 6 karakter rentan terhadap dictionary attack.

Fix: Semua validasi password diubah ke min_length[8] secara konsisten.
LOW PT-13 — CI_ENVIRONMENT = development di Production ⚠ Perlu Tindakan
OWASP A05:2021 — Security Misconfiguration  |  .env
Deskripsi

File .env masih menggunakan CI_ENVIRONMENT = development. Dalam mode ini, CI4 menampilkan stack trace penuh termasuk path server, variabel, dan potensi sensitive data saat terjadi error.

Tindakan (manual): Ubah di .env: 
CI_ENVIRONMENT = production
Dalam production mode, error page menampilkan pesan generik tanpa stack trace.
LOW PT-14 — Content Security Policy (CSP) Tidak Aktif ⚠ Perlu Tindakan
OWASP A05:2021 — Security Misconfiguration  |  Config/App.php
Deskripsi

$CSPEnabled = false — tidak ada Content Security Policy yang membatasi sumber script, style, dan resource. Tanpa CSP, serangan XSS yang berhasil menembus defense lain dapat mengeksekusi script arbitrary.

Tindakan (manual): Aktifkan CSP bertahap — mulai dengan report-only mode untuk audit, lalu terapkan policy ketat. Atau tambahkan CSP header manual di nginx/apache dengan policy minimal:
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'
INFO PT-15 — Google OAuth Callback Path Hardcode ✓ Fixed
Configuration Issue  |  Views/auth/google_oauth_callback.php
Deskripsi

File callback menggunakan hardcode /api/v1/... untuk fetch ke API. Pada deployment non-root (/DSK-DASH/public/), path tersebut salah dan OAuth flow gagal sepenuhnya.

Fix: Inject APP_BASE_URL dan APP_API_URL dari PHP ke JavaScript menggunakan base_url(). Fetch API menggunakan APP_API_URL yang benar.
